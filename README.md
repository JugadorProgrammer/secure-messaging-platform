# secure-messaging-platform
# AUTH

Сервис учётных записей решения Secure Messaging Platform.

### Требования к сервису учётных записей

#### Иерархия требований

```text
СЕРВИС УЧЁТНЫХ ЗАПИСЕЙ (AUTH)
    ├── общее
    │   ├── формат данных — JSON; ошибки — {"error": {"code", "message"}}
    │   ├── роли: user, admin
    │   ├── хранение паролей в виде хэшей
    │   └── регистрация с проверкой полей регулярными выражениями
    │
    ├── регистрация (POST /auth/signup)
    │   ├── создание пользователя
    │   └── возврат кодов восстановления
    │
    ├── трёхэтапная аутентификация
    │   ├── фактор 1 — логин и пароль (POST /auth/login)
    │   ├── фактор 2 — код из письма (POST /auth/login/email-code)
    │   ├── фактор 3 — одноразовый код (POST /auth/login/recovery-code)
    │   └── выдача токена после прохождения всех трёх факторов
    │
    ├── выход (POST /auth/logout)
    │
    ├── восстановление пароля
    │   ├── запрос письма (POST /auth/password/restore)
    │   └── код подтверждения + токен сброса + новый пароль
    │       (POST /auth/password/confirm)
    │
    ├── управление пользователями (admin)
    │   ├── список пользователей (GET /users)
    │   │   └── логин, почта, роль
    │   └── создание пользователя (POST /users)
    │       ├── логин, почта, пароль, роль
    │       └── возврат кодов восстановления
    │
    ├── взаимодействие с COORD
    │   ├── маршруты /auth/* и /users принимаются от COORD
    │   ├── IP пользователя передаётся в X-Forwarded-For
    │   └── проверка токена (POST /internal/introspect)
    │       ├── запрос: token
    │       ├── ответ: active, user_id, login, role
    │       └── active = true только после трёх факторов
    │
    └── почтовый сервер
        └── отправка одноразовых кодов для аутентификации
            и восстановления пароля
```
