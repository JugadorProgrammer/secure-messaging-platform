# Библиотека «Кузнечик» (DLL)

Блочный шифр по ГОСТ Р 34.12-2015 (блок 128 бит, ключ 256 бит, 10 раундов)
в режиме CBC с дополнением PKCS#7. Собрана как динамическая библиотека под
Windows: снаружи виден только C-интерфейс из `include/kuznyechik.h`.

## Состав

| Файл | Что внутри |
|---|---|
| `include/kuznyechik.h` | публичный контракт: статусы, размеры, функции |
| `src/kuz_tables.h`, `src/kuz_tables.cpp` | подстановка π, π⁻¹ и коэффициенты l |
| `src/block_cipher.h`, `src/block_cipher.cpp` | раунды, расписание ключа, шифрование и расшифровка блока |
| `src/cbc_mode.h`, `src/cbc_mode.cpp` | режим CBC, дополнение PKCS#7 |
| `src/api.cpp` | C-интерфейс: проверки, коды возврата, граница исключений |
| `src/hex.h`, `src/hex.cpp` | hex ↔ байты (для тестов, утилиты и самопроверки) |
| `tests/tests.cpp` | проверки: векторы ГОСТ, режим, контракт API |
| `tests/dll_check.cpp` | загрузка DLL через `LoadLibrary` и вызовы «как чужой программой» |
| `tools/kuz_cli.cpp` | демо-клиент: шифрование и расшифровка файлов |
| `docs/team-readme.md` | описание поставки для команды (копируется в `dist/README.md`) |
| `docs/example.cpp` | пример для команды (копируется в `dist/example.cpp`) |
| `docs/handover/` | руководство по сопровождению, вопросы нового разработчика, памятка и их `.docx` |
| `Makefile` | сборка, прогон проверок, очистка, поставка |
| `.gitignore` | артефакты сборки и `dist/` в репозиторий не идут |

## Сборка

Нужны `g++` (MinGW-w64, C++17) и `mingw32-make`. Проверялось на Windows x64,
g++ 15.2 (MSYS2 UCRT64).

```powershell
mingw32-make          # собрать всё
mingw32-make test     # собрать и прогнать проверки
mingw32-make dist     # собрать поставку для команды в dist/
mingw32-make clean    # удалить артефакты
```

### Поставка для команды

`mingw32-make dist` собирает папку `dist/` — это ровно то, что отдаём:

```
dist/
  kuznyechik.dll          сама библиотека
  libkuznyechik.dll.a     библиотека импорта
  kuznyechik.h            заголовок с контрактом
  example.cpp             минимальный пример шифрования и расшифровки
  README.md               краткое описание: как подключить и как вызывать
```

Исходники описания и примера лежат в `docs/`, чтобы `dist/` оставалась
полностью пересобираемой: правите `docs/team-readme.md` — повторяете
`mingw32-make dist`. Папка `dist/` в `.gitignore`: это снимок, а не исходники.

Появляются файлы:

- `kuznyechik.dll` — сама библиотека;
- `libkuznyechik.dll.a` — библиотека импорта, нужна программам, которые
  линкуются с DLL;
- `kuz_tests.exe` — проверки (статически с теми же исходниками, видят внутренности);
- `kuz_cli.exe` — демо-клиент, линкуется с DLL через `libkuznyechik.dll.a`;
- `dll_check.exe` — грузит DLL через `LoadLibrary` и вызывает функции по именам.

Флаги важны: `-Wall -Wextra -Wpedantic -Werror` (ноль предупреждений) и `-static`
у DLL — иначе она потянет `libstdc++-6.dll` и `libgcc_s_seh-1.dll`, которых
на машине команды может не быть.

## Контракт

| Функция | Назначение |
|---|---|
| `KuzVersion()` | версия строкой, например `"1.0.0"` |
| `KuzStatusMessage(status)` | текст ошибки для кода возврата |
| `KuzSelfTest()` | прогон встроенных векторов ГОСТ внутри библиотеки |
| `KuzCiphertextSize(data_size)` | сколько байт нужно под шифртекст (0 при переполнении) |
| `KuzEncrypt(key, key_size, iv, iv_size, data, data_size, out, out_capacity, out_size)` | шифрование |
| `KuzDecrypt(...)` | расшифровка, те же параметры |

Коды возврата:

| Код | Когда |
|---|---|
| `KUZ_STATUS_OK` | успех |
| `KUZ_STATUS_INVALID_KEY` | ключ не 32 байта |
| `KUZ_STATUS_INVALID_IV` | IV не 16 байт |
| `KUZ_STATUS_INVALID_ARGUMENT` | `NULL` там, где нужен указатель; размер шифртекста не кратен 16 или равен 0 |
| `KUZ_STATUS_BUFFER_TOO_SMALL` | буфер мал; в `*out_size` лежит нужный размер |
| `KUZ_STATUS_INVALID_PADDING` | после расшифровки неверное дополнение: чужой ключ, чужой IV или испорченные данные |
| `KUZ_STATUS_INTERNAL_ERROR` | непредвиденная ошибка внутри |

Правила, на которые можно рассчитывать:

1. **Память выделяет вызывающая сторона.** Библиотека только пишет в `out`
   и никогда не возвращает указатели на свои буферы. Кто выделил — тот освобождает.
2. **`*out_size` заполняется всегда**: при успехе — сколько записано, при нехватке
   места — сколько нужно. Один повторный вызов с буфером нужного размера.
3. **Шифртекст всегда кратен 16 байтам.** Пустой ввод даёт один блок дополнения
   (`0x10` × 16), при расшифровке он возвращает пустые данные.
4. **Исключения не выходят за границу DLL.** Внутри — `throw`, на границе —
   `catch (...)`, наружу — только код возврата.
5. **Функции без состояния**, поэтому их можно вызывать из нескольких потоков
   одновременно. Ключ и IV передаются в каждом вызове.
6. **Закрытый текст и ключ не логируются** и никуда не пишутся: библиотека работает
   только с переданными буферами.

## Пример на C++

```cpp
#include <cstdint>
#include <vector>

#include "kuznyechik.h"

std::vector<std::uint8_t> Encrypt(const std::vector<std::uint8_t>& key,
                                  const std::vector<std::uint8_t>& iv,
                                  const std::vector<std::uint8_t>& data) {
    std::vector<std::uint8_t> ciphertext(KuzCiphertextSize(data.size()));
    std::size_t written = 0;

    const KuzStatus status =
        KuzEncrypt(key.data(), key.size(), iv.data(), iv.size(), data.data(),
                   data.size(), ciphertext.data(), ciphertext.size(), &written);
    if (status != KUZ_STATUS_OK) {
        throw std::runtime_error(KuzStatusMessage(status));
    }

    ciphertext.resize(written);
    return ciphertext;
}
```

Программа, которая линкуется с DLL, должна получить `libkuznyechik.dll.a`
при сборке, а `kuznyechik.dll` — рядом с `.exe` при запуске.

## Демонстрация

```powershell
# ключ и IV — hex; ключ 32 байта, IV 16 байт
kuz_cli.exe selftest

kuz_cli.exe encrypt 8899aabbccddeeff0011223344556677fedcba98765432100123456789abcdef `
                    1234567890abcdef1234567890abcdef `
                    message.txt ciphertext.hex

kuz_cli.exe decrypt 8899aabbccddeeff0011223344556677fedcba98765432100123456789abcdef `
                    1234567890abcdef1234567890abcdef `
                    ciphertext.hex restored.txt
```

Текст `Привет, это Кузнечик!` занимает 38 байт в UTF-8 и превращается
в 48 байт шифртекста (три блока):

```
035bbcad4bab4cbc16cdbe732abc6d93
9843ba6b135e8c6c67604ef80ee78ec0
679401b41dd575c8ce929a5bccf048a0
```

Расшифровка возвращает исходные байты (проверяется сравнением файлов).
В CLI шифртекст хранится hex-текстом, чтобы его можно было посмотреть глазами;
на проводе в проекте он передаётся в base64 — это задача вызывающей стороны.

## Что проверяется

`kuz_tests.exe` печатает `All checks passed` и прогоняет:

- **преобразования по стандарту**: S, R, L, L⁻¹, раундовые константы C₁–C₈,
  раундовые ключи K₁–K₁₀ и шифрование/расшифровка тестового блока
  (примеры 5.1–5.6 ГОСТ Р 34.12-2015 / RFC 7801);
- **взаимная обратность**: π и π⁻¹, R и R⁻¹, L и L⁻¹;
- **дополнение**: пустой ввод, 15 байт, некорректные значения (ноль, `0x11`,
  несогласованные байты);
- **режим CBC**: длины 0, 1, 15, 16, 17, 31, 32, 33, 1000 — размер и round trip;
- **контракт API**: `NULL`-указатели, длины ключа и IV, малый буфер и размер
  в `*out_size`, неверное дополнение, пустой ввод;
- **служебное**: `KuzSelfTest`, версия, тексты ошибок.

`dll_check.exe` дополнительно проверяет, что DLL действительно грузится
и отдаёт нужные функции по именам (без import library).

Экспортируется ровно шесть функций, без C++-манглинга:

```
KuzCiphertextSize, KuzDecrypt, KuzEncrypt, KuzSelfTest, KuzStatusMessage, KuzVersion
```

Зависимости DLL — только системные (`KERNEL32.dll` и `api-ms-win-crt-*`),
проверяется командой:

```powershell
objdump -p kuznyechik.dll | Select-String 'DLL Name:'
```

## Ограничения и известный долг

Базовая версия намеренно простая; часть этого пойдёт в работу № 5 (рефакторинг),
часть — в работу № 6 (архитектура и паттерн «фасад»):

1. Линейное преобразование реализовано «в лоб» через 16 применений R; табличная
   реализация была бы в разы быстрее.
2. Проверки аргументов в `KuzEncrypt` и `KuzDecrypt` почти одинаковые.
3. В `EncryptCbc`/`DecryptCbc` смешаны цикл по блокам и работа с дополнением.
4. В тестах и утилите есть числа 16 вместо имён размеров.
5. Ключ и открытый текст не затираются в памяти после использования.
6. Нет аутентификации (CMAC/GCM): режим CBC не защищает от подмены шифртекста,
   это видно по коду `KUZ_STATUS_INVALID_PADDING` — он срабатывает не всегда.
7. CBC не скрывает точную длину сообщения: шифртекст кратен 16 байтам.
8. Нет CI: проверки запускаются вручную через `mingw32-make test`.
