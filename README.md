# COORD

Координационный сервис решения Secure Messaging Platform

### Требования к координационному сервису

#### Иерархия требований к координационному сервису

```
КООРДИНАЦИОННЫЙ СЕРВИС (BACK)
    ├── общее
    │   ├── единая точка входа для Front, все эндпоинты с префиксом /api
    │   ├── формат данных — JSON; ошибки — {"error": {"code", "message"}}
    │   ├── защищённые эндпоинты — заголовок Authorization: Bearer <token>
    │   └── роли: user, admin
    ├── публичные эндпоинты (без токена)
    │   ├── список ролей с доступными экранами и полномочиями (GET /roles)
    │   ├── список методов шифрования: код, название, размер ключа, признак включённости (GET /methods)
    │   └── проверка подписанного PDF-документа: файл → подпись верна / документ изменён, кто и когда подписал (POST /verify)
    ├── вход и регистрация (перенаправляются в сервис учётных записей без изменений)
    │   ├── регистрация, возвращает коды восстановления (POST /auth/signup)
    │   ├── фактор 1 — логин и пароль (POST /auth/login)
    │   ├── фактор 2 — код из письма (POST /auth/login/email-code)
    │   ├── фактор 3 — одноразовый код, возвращает токен (POST /auth/login/recovery-code)
    │   ├── выход (POST /auth/logout)
    │   ├── запрос письма для восстановления пароля (POST /auth/password/restore)
    │   └── код подтверждения + токен сброса + новый пароль (POST /auth/password/confirm)
    ├── рабочий стол (user, admin)
    │   ├── текущий пользователь: id, логин, роль (GET /me)
    │   ├── шифрование сообщения. Контракт: исходный текст + метод (rsa | kuznyechik) (POST /messages)
    │   │   ├── выключенный администратором метод — ошибка method_disabled
    │   │   ├── Кузнечик: новый ключ 256 бит и IV на каждое сообщение
    │   │   └── RSA: пара ключей 32768 бит у каждого пользователя своя, создаётся один раз;
    │   │       пока создаётся — ошибка key_generating
    │   ├── журнал сообщений: user — только свои, admin — всех пользователей (GET /messages?limit=&offset=)
    │   ├── одно сообщение (GET /messages/{id})
    │   ├── DTO сообщения
    │   │   ├── id, владелец, временная метка
    │   │   ├── метод и размер ключа (rsa 32768 | kuznyechik 256)
    │   │   ├── исходный текст, шифртекст (hex)
    │   │   ├── время генерации ключа, шифрования, дешифрования (мс)
    │   │   └── ключи — только владельцу сообщения, для остальных поле отсутствует
    │   │       ├── RSA: публичный и закрытый ключ, PEM (PKCS #1)
    │   │       └── Кузнечик: ключ и IV, hex
    │   ├── дешифрование (POST /decrypt)
    │   │   ├── RSA: шифртекст + закрытый ключ PEM + метод
    │   │   ├── Кузнечик: шифртекст + ключ + IV + метод
    │   │   └── необязательно id сообщения — тогда сохраняется время дешифрования
    │   └── PDF-документ с встроенной ЭЦП: исходный текст, метод, размер ключа, шифртекст, время операций (GET /messages/{id}/pdf)
    │       ├── только для владельца сообщения
    │       └── подпись — RSA над хешем Стрибог-512, системный ключ подписи
    ├── администратор (admin)
    │   ├── включение / выключение метода шифрования (PATCH /methods/{code})
    │   ├── список пользователей: логин, почта, роль (GET /users) — перенаправляется в сервис учётных записей
    │   └── создание пользователя: логин, почта, пароль, роль, возвращает коды восстановления (POST /users) — перенаправляется в сервис учётных записей
    ├── взаимодействие с сервисом учётных записей
    │   ├── все пути /auth/* и /users перенаправляются как есть, IP пользователя — в X-Forwarded-For
    │   └── проверка токена на каждом защищённом запросе (POST /internal/introspect)
    │       ├── запрос: токен
    │       └── ответ: active, user_id, login, role; active = true только после всех трёх факторов
    └── взаимодействие с криптографическим модулем (REST, JSON)
        ├── кодировки: данные — base64, ключ и IV Кузнечика — hex, ключи RSA — PEM (PKCS #1)
        ├── в ответах на операции — время выполнения duration_ms (без учёта сети)
        ├── ошибки: 400 — неверный ключ или данные, 5xx — внутренняя ошибка
        ├── генерация пары RSA: bits → публичный и закрытый ключ (POST /rsa/keys)
        ├── шифрование RSA: публичный ключ + данные → шифртекст (POST /rsa/encrypt)
        ├── дешифрование RSA: закрытый ключ + шифртекст → данные (POST /rsa/decrypt)
        ├── генерация ключа и IV Кузнечика (POST /kuznyechik/keys)
        ├── шифрование Кузнечиком: ключ + IV + данные → шифртекст (POST /kuznyechik/encrypt)
        ├── дешифрование Кузнечиком: ключ + IV + шифртекст → данные (POST /kuznyechik/decrypt)
        ├── хеш Стрибог-512: данные → хеш (POST /streebog512)
        ├── подпись: закрытый ключ + данные → подпись (POST /sign)
        └── проверка подписи: публичный ключ + данные + подпись → верна / нет (POST /verify)
```
